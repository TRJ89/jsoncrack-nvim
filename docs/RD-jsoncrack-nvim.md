# JSON Crack Preview for Neovim — 要件定義

## 1. 目的

Neovimで編集中のJSON/YAMLファイルを、JSON Crackのインタラクティブなグラフとしてブラウザ上でプレビューできるOSSプラグインを開発する。

**LazyVimのMarkdown Previewと同じくらい気軽に使えること**を最も重要な目標とする。

### 想定するユーザー体験

1. LazyVimでJSON/YAMLファイルを開く。
2. `<leader>jp` でプレビューを開始する。
3. ブラウザにJSON Crackのグラフが表示される。
4. Neovimで編集・保存すると、グラフが自動更新される。
5. バッファを切り替えると、そのプレビューは終了する。
6. ブラウザのタブを閉じるだけでも、ユーザーはプレビューを終えられる。

プレビューの開始・終了を意識せず、必要なときだけ使えることを重視する。

## 2. 開発方針

- **MVPはLazyVim + Linuxを動作保証対象とする。**
- Neovimの標準APIを優先し、LazyVimへの依存は最小化する。
- JSON Crackのグラフ描画機能を再実装しない。
- 既存OSSを最大限活用する。
- 利用者のセットアップと実行時依存を最小限にする。
- 必要性が明確でない設定項目や抽象化を増やさない。
- MVPの完成を優先し、便利機能の追加は後回しにする。

### 参考にする既存プラグイン

[**iamcco/markdown-preview.nvim**](https://github.com/iamcco/markdown-preview.nvim)

LazyVimの `<leader>cp` で使用されるMarkdown Preview。

特に以下を参考にする。

- キーマップからのプレビュー起動・停止
- バッファ非表示時のプレビュー終了
- Neovimとブラウザの連携
- プレビューサーバーのライフサイクル管理

既存実装をそのまま複製する必要はない。

## 3. 機能要件

優先度の定義：

- **P0：必須。** MVPの完成条件。
- **P1：推奨。** 実装が容易なら採用する。
- **P2：任意。** 複雑になるなら実装しない。

### 3.1 プレビューの起動・停止（P0）

- `<leader>jp` でプレビューを起動・停止する。
- `:JsonCrackPreviewToggle` コマンドを提供する。
- 現在のJSON/YAMLバッファをプレビュー対象とする。
- ブラウザはOSの既定ブラウザを使用する。
- 起動済みの場合にサーバーを重複起動しない。
- プレビュー停止時に関連するリソースを解放する。
- 非対応ファイル形式では適切なメッセージを表示する。

明示的な `:JsonCrackPreviewStop` コマンドは提供してもよいが、必須ではない。

### 3.2 バッファ切り替え時の終了（P0）

- プレビュー対象のバッファが非表示になったら、そのプレビューを終了する。
- 別のバッファへプレビュー対象を自動的に切り替える必要はない。
- 次のJSON/YAMLファイルをプレビューする場合は、改めてプレビューを起動する。

Markdown Previewの `BufHidden` を利用した処理を参考にする。

ブラウザタブを自動で閉じられるかはブラウザの制約に依存するため、タブを強制的に閉じること自体は必須としない。

ただし、プレビューは終了状態になり、再び起動できること。

### 3.3 ブラウザタブを閉じた場合（P0/P2）

**P0：基本要件**

- ブラウザタブはユーザーが普通に閉じられる。
- タブを閉じてもNeovim側でエラーが発生しない。
- タブを閉じた後でも、改めてプレビューを起動できる。
- Neovim終了時や明示的なプレビュー停止時には、サーバーを適切に終了する。

**P2：任意要件**

最後のブラウザプレビュー接続がなくなった際、サーバーを自動終了する機能。

これは必須要件ではない。

実装が容易で、ライフサイクル管理が複雑にならない場合に限り採用する。

- 接続切断を監視するためだけに複雑な通信基盤を導入しない。
- タブの再読み込みを誤って終了と判定しないようにする。
- 実装が複雑なら、ブラウザタブを閉じてもサーバーが残る挙動で問題ない。
- この機能を実装しなくてもMVPの完成条件を満たす。

**自動終了を実現することより、シンプルな実装を優先する。**

### 3.4 対応ファイル形式（P0）

- JSON（`.json`）
- YAML（`.yaml`、`.yml`）

JSON/YAMLをグラフ描画に必要なデータ構造へ変換する。

対応する主な値：

- Object / Mapping
- Array / Sequence
- String
- Number
- Boolean
- Null

YAML固有の特殊構文をすべてサポートする必要はない。

変換できない入力は黙って誤表示せず、エラーを通知する。

### 3.5 自動更新（P0）

- Neovimでファイルを保存するとプレビューが自動更新される。
- ブラウザの手動再読み込みは不要。
- 更新は保存からおおむね1秒以内を目標とする。
- 変更がない場合の不要な再描画を避ける。
- 構文エラー時はエラーを表示する。
- 構文エラー修正後、保存すると正常なプレビューに復帰する。
- エラー発生時には、可能なら最後の正常なグラフを維持する。

更新方法は `BufWritePost` による通知、HTTPポーリングなどを比較し、最もシンプルな方式を選択する。

未保存バッファのリアルタイム更新はMVP対象外とする。

### 3.6 グラフ表示（P0）

JSON Crack公式コンポーネントを利用する。

- JSON/YAMLの階層構造をノードとエッジで可視化する。
- ズーム・パン操作ができる。
- ノードの内容を確認できる。
- ダークテーマで利用できる。
- その他、コンポーネントが標準提供する操作を使用できる。

ノードの操作機能やレイアウト機能は既存コンポーネントに委ねる。

独自のグラフ描画エンジンは実装しない。

## 4. 推奨技術構成

### 4.1 全体アーキテクチャ

```text
Neovim / LazyVim
      │
      │ Lua plugin
      │
      ├── Preview Toggle
      ├── BufHidden
      └── BufWritePost
              │
              ▼
       Local HTTP Server
              │
              ├── ファイル内容の提供
              ├── 更新検知・通知
              └── 静的Webアプリの配信
                        │
                        ▼
                 Browser / Firefox
                        │
                        ├── JSON/YAML解析
                        └── jsoncrack-react
                                │
                                ▼
                         Graph Preview
```

図は概念的な構成であり、具体的な通信方式や解析処理の配置は実装時に判断する。

### 4.2 グラフ描画：jsoncrack-react

第一候補：

**[jsoncrack-react](https://github.com/AykutSarac/jsoncrack.com/tree/main/packages/jsoncrack-react)**

JSON Crack公式のReactコンポーネント。

採用理由：

- JSON Crackの描画機能を再利用できる。
- グラフ描画処理を自作する必要がない。
- 独立したWebアプリに組み込める。
- iframe経由でJSON Crack本体のWebサイトに依存する必要がない。

実装前に現行API、依存関係、ライセンス条件を確認すること。

### 4.3 フロントエンド：React + TypeScript

`jsoncrack-react` を利用する場合、Reactは依存関係として必要。

推奨構成：

- React
- TypeScript
- jsoncrack-react
- YAML解析ライブラリ（必要な場合）

Reactはブラウザ側の描画に限定する。

NeovimやHTTPサーバー側でReactを実行する必要はない。

### 4.4 ビルドツール：Vite

Viteを第一候補とするが、必須ではない。

- 開発・ビルド時に使用する。
- ビルド済みのHTML/JS/CSSを配布する。
- 利用時にはViteの開発サーバーを起動しない。
- 利用者に `npm install` や `npm run build` を要求しない。

他のビルドツールで明らかに構成が簡単になるなら変更してよい。

依存関係や配布サイズを過度に増やさないこと。

### 4.5 Neovim側：Lua

Neovim標準APIを利用する。

参考API：

| API | 用途 |
|---|---|
| `nvim_create_user_command` | コマンド登録 |
| `vim.keymap.set` | ショートカット |
| `nvim_create_autocmd` | バッファ・終了イベント |
| `vim.fn.jobstart` / `jobstop` | 外部サーバーの起動・停止 |
| `vim.ui.open` | 既定ブラウザを開く |
| `vim.notify` | 通知・エラー表示 |

必要な処理は非同期化し、Neovimの操作をブロックしない。

### 4.6 ローカルHTTPサーバー

実装方式は固定しない。

候補：

1. **Neovim Lua + `vim.uv`**
   - 外部ランタイムが不要
   - HTTP処理は実装・保守が必要

2. **Python標準ライブラリ**
   - 小規模なHTTPサーバーを比較的簡単に実装できる
   - Pythonへの実行時依存が発生する

必要であればNode.jsなどの構成も比較してよいが、実行時依存を増やす明確な理由が必要。

選定基準：

- 実装コードの少なさ
- 利用者のセットアップの簡単さ
- プロセス管理の容易さ
- セキュリティ
- 保守性

### 4.7 更新通知

候補：

- `BufWritePost` からの通知
- HTTPポーリング
- Server-Sent Events（SSE）

WebSocketやSocket.IOは必須としない。

MVPで必要なのは、保存後にブラウザのグラフが更新されることだけである。

**通信方式そのものに要件はない。最も簡潔に要件を満たせる方式を選択する。**

## 5. 非機能要件

### 5.1 導入・配布

- lazy.nvim経由でインストールできる。
- LazyVimの設定例をREADMEに記載する。
- 利用時のWebアプリビルドを不要にする。
- プラグインのインストールだけで必要な静的アセットが利用できる。
- 外部Webサービスに依存せず、オフラインで動作する。

### 5.2 パフォーマンス

- Neovimの編集操作をブロックしない。
- 変更のないファイルを無駄に再解析・再描画しない。
- 大きなファイルを読み込んでもNeovimが操作不能にならない。
- ノード数やグラフサイズの制限は、可能なら `jsoncrack-react` が持つ機能を活用する。

独自の描画最適化はMVP対象外。

### 5.3 セキュリティ

- HTTPサーバーは `127.0.0.1` にバインドする。
- 利用可能なポートを自動選択する。
- 任意のローカルファイルを読み取れるAPIを公開しない。
- プレビュー対象以外のファイルにアクセスさせない。
- JSON/YAMLの内容を外部サービスへ送信しない。
- 実行時にCDN等へ依存しない。
- ローカルHTTPサーバーに必要なアクセス制限を実装する。

### 5.4 ライフサイクル

- Neovim終了時にはサーバーを停止する。
- 明示的なプレビュー停止時にもサーバーを停止する。
- 起動・停止の繰り返しでプロセスを増殖させない。
- サーバーが停止しても次回のプレビューを正常に起動できる。
- 複数のNeovimプロセス間でポートが衝突しない。

ブラウザタブを閉じた際の自動終了については、前述のとおり任意とする。

## 6. MVP対象外

以下は初期実装では不要。

- 未保存バッファのリアルタイムプレビュー
- バッファ切り替えへの自動追従
- 複数ファイルの同時プレビュー
- Neovimカーソルとグラフノードの同期
- ブラウザからNeovimへの編集反映
- XML、TOML、CSV対応
- SSHリモート環境への自動対応
- Windows/macOSの動作保証
- 独自グラフエンジン
- 複雑な設定UI
- JSON Crack本体の全機能再現
- **ブラウザタブ終了時のサーバー自動終了（任意機能）**

## 7. MVP受け入れ条件

### 必須

- [ ] LazyVimに導入できる。
- [ ] `<leader>jp` でプレビューを開始・停止できる。
- [ ] JSONファイルをグラフ表示できる。
- [ ] YAMLファイルをグラフ表示できる。
- [ ] 保存するとグラフが自動更新される。
- [ ] 手動でブラウザを再読み込みする必要がない。
- [ ] 構文エラー時の表示と復帰が正しく動作する。
- [ ] バッファが非表示になるとプレビューが終了する。
- [ ] ブラウザタブを手動で閉じても問題が起きない。
- [ ] プレビューを再起動できる。
- [ ] Neovim終了時にサーバーが停止する。
- [ ] 不要なサーバープロセスが増殖しない。
- [ ] ビルド済みアセットで動作する。
- [ ] 外部Webサービスへの接続なしで動作する。
- [ ] READMEに導入・使用・開発手順がある。

### 任意

- [ ] 最後のブラウザタブを閉じるとサーバーが自動終了する。
- [ ] グラフの更新時にズーム・パン状態が維持される。
- [ ] ダーク/ライトテーマを自動切り替えできる。

任意項目が未実装でもMVPは完成とする。

## 9. Codexへの実装指示

### 最初に調査すること

1. `iamcco/markdown-preview.nvim` の起動・終了・バッファ切り替え時の動作を確認する。
2. `jsoncrack-react` の現行APIと依存関係を確認する。
3. 類似するNeovimプラグインが存在しないか調査する。
4. LuaとPythonによるローカルサーバーの実装コストを比較する。
5. 実装の最も単純な構成を決める。

### 実装の進め方

1. JSONのグラフ表示を実現する。
2. YAML対応を追加する。
3. Neovimからの起動・停止を実装する。
4. 保存時の自動更新を実装する。
5. バッファ切り替え・Neovim終了時の処理を実装する。
6. テストとREADMEを整備する。
7. 任意機能は必要性と実装コストを評価して判断する。

### 判断基準

要件を満たす方法が複数ある場合は、次の優先順位で判断する。

1. ユーザー体験がシンプルであること
2. 実装と保守がシンプルであること
3. 実行時依存が少ないこと
4. 十分な安定性・性能があること
5. 拡張性があること

将来の拡張性のためだけに、現時点で不要な抽象化を追加しない。

特に、**ブラウザタブを閉じた際のサーバー自動終了は、実装コストが低い場合のみ採用する任意の改善**であり、その実現のために複雑な仕組みを導入してはならない。

## 最終目標

**JSON/YAML版のMarkdown Previewを作る。**

JSON Crackの高度な描画機能を利用しながら、Neovim側の操作はプレビューの起動・停止と保存時更新に限定する。

高度な機能を備えた汎用ツールよりも、日常的に気軽に利用できる、小さく保守しやすいOSSを目指す。
